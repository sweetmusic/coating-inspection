# coating-inspection

사외 철의장 도장 협력사 품질점검 모바일 앱.

- `inspection_app.html` : 점검 앱
- `app_config.json` : 체크시트·협력사·등급 설정 (앱이 GitHub Pages에서 자동 로드)
- `docs/report-data-format.md` : HTML 보고서에 내장된 데이터 블록 형식 (사내 업로드용)

## 체크시트 수정 규칙 (`app_config.json`)

보고서 데이터는 세부항목 ID(`2-1-2` 등)로 항목을 구분합니다.
과거 점검 결과와 추이를 정확히 비교하려면 아래 규칙을 지켜 주세요.

### 1. 항목 ID는 바꾸거나 재사용하지 않는다
- **삭제**: 항목을 지우지 말고 `"active": false`로 바꿉니다. 앱 화면·점수·보고서에서 빠집니다.
  - 중분류(예: `2-1`) 전체를 빼려면 중분류에 `"active": false`를 넣어도 됩니다.
- **추가**: 해당 중분류의 **다음 번호**를 씁니다 (예: `2-1-2` 다음은 `2-1-3`).
  삭제된 번호를 다시 쓰거나, 번호를 당겨서 다시 매기지 않습니다.
- 새 항목에는 `"active": true`, `"since": "추가된 버전"`을 넣습니다.

```json
{ "id": "2-1-3", "active": true, "since": "v1.1", "options": [ ... ] }
```

### 2. 바뀌면 버전을 올린다 (`meta.version`, `meta.updated_at`)
| 변경 내용 | 버전 |
|---|---|
| 선택지 문구, 배점 변경 | v1.0 → **v1.1** |
| 항목 추가·사용 중지, 대분류 구성 변경 | v1.x → **v2.0** |
| 협력사 목록, 등급 문구만 변경 | 올리지 않아도 됨 (`updated_at`만 갱신) |

### 3. 바꾸기 전 파일을 보관한다
수정 전에 현재 파일을 `config_history/app_config_v1.0.json`처럼 버전명으로 복사해 둡니다.
사내 웹앱에서 과거 버전 체크시트를 참조할 때 사용합니다.

> 보고서에는 작성 당시의 항목명·선택지·배점이 함께 저장되므로, 체크시트가 바뀌어도 과거 보고서는 그대로 재현됩니다.
> 배점이 다른 버전끼리 비교할 때는 원점수 대신 환산점수(100점 기준)를 사용하세요.

## 화면 스위치 (`app_config.json` → `meta`)

| 키 | 값 | 설명 |
|---|---|---|
| `show_excel` | `true` / `false` | 결과 화면의 **📊 엑셀** 버튼 표시 여부. 사내 HTML 업로드가 준비되면 `false`로 바꿉니다. |

- 앱은 저장된 설정으로 바로 시작한 뒤, 인터넷이 연결되어 있으면 GitHub의 최신 설정을 확인합니다.
  - `show_excel`은 확인 즉시 반영됩니다.
  - 체크시트·협력사 등 나머지 변경은 점검 시작 전이면 바로, 점검 중이면 작성 중인 점검을 보호하기 위해 **다음에 앱을 열 때** 적용됩니다.
- 엑셀 버튼이 숨겨져도 **🖨️ 보고서 → 📤 HTML** 저장 시 진행 중 작업이 보관함으로 정리되므로 동작에는 문제가 없습니다.
